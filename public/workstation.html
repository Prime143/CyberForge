System Directive & Rules of Engagement
CyberForge Operational Directive // Standards of Engagement

Section A — Strategic Purpose

CyberForge operates as an open, student-led national engineering proving ground and skills incubator. The facility bridges theoretical computer science education into disciplined, production-grade engineering practice through live-infrastructure sprints. Candidates build defensive tooling, security verification suites, and fault-tolerant software engineered for public utility, civic governance, and national infrastructure.

Section B — Standards of Engagement

  • Credential Non-Disclosure: Access keys are non-transferable cryptographic credentials bound to single candidates. Disclosure or sharing triggers immediate revocation.
  • Telemetry Integrity: Zero tolerance for heartbeat spoofing, automated keep-alive inflation, or synthetic interaction generators. Telemetry monitors workstation focus versus external tooling to ensure realistic production discipline.
  • Hard Deadlines: Deliverables must be submitted before deadline expiration. Automated sweepers flag overdue tasks every 60 seconds.
  • Code Hygiene & Verification: All submitted software must be defensive, parameterized against SQL injection, resilient to malformed payloads, and accompanied by verifiable test suites.

Section C — Immutable Auditing & Non-Repudiation

All workstation interactions—including authentication handshakes, state transitions, milestone checkpoints, and artifact submissions—are committed to an immutable append-only audit trail. This records candidate progression objectively for technical certifications and recommendations.
